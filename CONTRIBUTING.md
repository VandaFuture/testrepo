Diretrizes de contribuição - Regras para submissão de pull requests:

Descrição Clara: Certifique-se de que a descrição do pull request seja clara e detalhada. Explique o problema que está resolvendo e as mudanças que fez.
Referência a Issues: Se o pull request estiver relacionado a uma issue, mencione o número da issue na descrição.
Testes: Inclua testes para garantir que suas mudanças funcionem conforme esperado. Descreva como os testes foram realizados e os resultados obtidos.
Documentação: Atualize a documentação relevante para refletir as mudanças feitas. Isso pode incluir README, wiki, ou outros arquivos de documentação.
Estilo de Código: Siga o estilo de código do projeto. Utilize ferramentas de linting e formatação para garantir consistência.
Commits: Faça commits pequenos e focados. Cada commit deve representar uma mudança lógica e autônoma.
Revisão de Código: Esteja aberto a feedback durante a revisão de código. Responda aos comentários e faça as alterações necessárias.
Testes Automatizados: Certifique-se de que todos os testes automatizados passem antes de enviar o pull request.
Conflitos de Merge: Resolva quaisquer conflitos de merge antes de enviar o pull request.
Checklist: Inclua uma checklist no pull request para garantir que todos os requisitos foram atendidos.
